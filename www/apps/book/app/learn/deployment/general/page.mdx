## What You'll Deploy

When you deploy the Arcangel application, you need to deploy the following resources:

1. PostgreSQL database: This is the database that will hold your Arcangel application's details.
2. Redis database: This is the database that will store the Arcangel server's session.
3. Arcangel application in [server and worker mode](../../production/worker-mode/page.mdx), where:
    - The server mode handles incoming API requests and serving the Arcangel Admin dashboard.
    - The worker mode handles background tasks, such as scheduled jobs and subscribers.

So, when choosing a hosting provider, make sure it supports deploying these resources. Also, for optimal experience, the hosting provider and plan must offer at least 2GB of RAM.

## 1. Configure Arcangel Application

### Worker Mode

The `workerMode` configuration determines which mode the Arcangel application runs in. When you deploy the Arcangel application, you deploy two instances: one in server mode, and one in worker mode.

Learn more about worker mode in the [Worker Module chapter](../../production/worker-mode/page.mdx).

So, add the following configuration in `arcangel-config.ts`:

```ts title="arcangel-config.ts"
module.exports = defineConfig({
  projectConfig: {
    // ...
    workerMode: process.env.ARCANGEL_WORKER_MODE as "shared" | "worker" | "server",
  },
})
```

Later, you’ll set different values of the `ARCANGEL_WORKER_MODE` environment variable for each Arcangel application deployment or instance.

### Configure Arcangel Admin

The Arcangel Admin is served by the Arcangel server application. So, you need to disable it in the worker Arcangel application only.

To disable the Arcangel Admin in the worker Arcangel application while keeping it enabled in the server Arcangel application, add the following configuration in `arcangel-config.ts`:

```ts title="arcangel-config.ts"
module.exports = defineConfig({
  // ...
  admin: {
    disable: process.env.DISABLE_ARCANGEL_ADMIN === "true",
  },
})
```

Later, you’ll set different values of the `DISABLE_ARCANGEL_ADMIN` environment variable for each Arcangel application instance.

### Configure Redis URL

The `redisUrl` configuration specifies the connection URL to Redis to store the Arcangel server's session.

<Note>

Learn more in the [Arcangel Configuration documentation](../../configurations/arcangel-config/page.mdx#redisurl).

</Note>

So, add the following configuration in `arcangel-config.ts` :

```ts title="arcangel-config.ts"
module.exports = defineConfig({
  projectConfig: {
    // ...
    redisUrl: process.env.REDIS_URL,
  },
})
```

## 2. Add predeploy Script

Before you start the Arcangel application in production, you should always run migrations and sync links.

So, add the following script in `package.json`:

```json
"scripts": {
  // ...
  "predeploy": "arcangel db:migrate"
},
```

## 3. Install Production Modules and Providers

By default, your Arcangel application uses modules and providers useful for development, such as the Local File Module Provider.

It’s highly recommended to instead use modules and providers suitable for production, including:

- [Redis Caching Module](!resources!/infrastructure-modules/caching/providers/redis)
- [Redis Event Bus Module](!resources!/infrastructure-modules/event/redis)
- [Workflow Engine Redis Module](!resources!/infrastructure-modules/workflow-engine/redis)
- [Redis Locking Module Provider](!resources!/infrastructure-modules/locking/redis)
- [PostHog Analytics Module Provider](!resources!/infrastructure-modules/analytics/posthog) (If you're using analytics in your application. You can also use other analytics module providers that are production-ready).
- [S3 File Module Provider](!resources!/infrastructure-modules/file/s3) (or other file module providers that are production-ready).
- [SendGrid Notification Module Provider](!resources!/infrastructure-modules/notification/sendgrid) (or other notification module providers that are production-ready).

<Note>

The Caching Module was introduced in [Arcangel v2.11.0](https://github.com/arcangel/arcangel/releases/tag/v2.11.0) to replace the deprecated Cache Module.

</Note>

Then, add these modules in `arcangel-config.ts`:

```ts title="arcangel-config.ts"
import { Modules } from "@arcangel/framework/utils"

module.exports = defineConfig({
  // ...
  modules: [
    {
      resolve: "@arcangel/arcangel/caching",
      options: {
        providers: [
          {
            resolve: "@arcangel/caching-redis",
            id: "caching-redis",
            is_default: true,
            options: {
              redisUrl: process.env.CACHE_REDIS_URL,
            },
          },
        ],
      },
    },
    {
      resolve: "@arcangel/arcangel/event-bus-redis",
      options: {
        redisUrl: process.env.REDIS_URL,
      },
    },
    {
      resolve: "@arcangel/arcangel/workflow-engine-redis",
      options: {
        redis: {
          // Note: This was `url` before v2.12.2
          // It's now deprecated in favor of `redisUrl`
          redisUrl: process.env.REDIS_URL,
        },
      },
    },
    {
      resolve: "@arcangel/arcangel/locking",
      options: {
        providers: [
          {
            resolve: "@arcangel/arcangel/locking-redis",
            id: "locking-redis",
            is_default: true,
            options: {
              redisUrl: process.env.LOCKING_REDIS_URL,
            },
          },
        ],
      },
    },

  ],
})
```

<Note title="Tip">

Check out the [Integrations](!resources!/integrations) and [Infrastructure Modules](!resources!/infrastructure-modules) documentation for other modules and providers to use.

</Note>

## 4. Create PostgreSQL and Redis Databases

Your Arcangel application must connect to PostgreSQL and Redis databases. So, before you deploy it, create production PostgreSQL and Redis databases.

If your hosting provider doesn't support databases, you can use [Neon for PostgreSQL database hosting](https://neon.tech/), and [Redis Cloud for the Redis database hosting](https://redis.io/cloud/).

After hosting both databases, keep their connection URLs for the next steps.

## 5. Deploy Arcangel Application in Server Mode

As mentioned earlier, you'll deploy two instances or create two deployments of your Arcangel application: one in server mode, and the other in worker mode.

The deployment steps depend on your hosting provider. This section provides the general steps to perform during the deployment.

### Set Environment Variables

When setting the environment variables of the Arcangel application, set the following variables:

```bash
COOKIE_SECRET=supersecret # TODO GENERATE SECURE SECRET
JWT_SECRET=supersecret  # TODO GENERATE SECURE SECRET
STORE_CORS= # STOREFRONT URL
ADMIN_CORS= # ADMIN URL
AUTH_CORS= # STOREFRONT AND ADMIN URLS, SEPARATED BY COMMAS
DISABLE_ARCANGEL_ADMIN=false
ARCANGEL_WORKER_MODE=server
PORT=9000
DATABASE_URL= # POSTGRES DATABASE URL
REDIS_URL= # REDIS DATABASE URL
```

Where:

- The value of `COOKIE_SECRET` and `JWT_SECRET` must be a randomly generated secret. These are required in production. If not set, an error is thrown when starting the Arcangel application.
- `STORE_CORS`'s value is the URL of your storefront. If you don’t have it yet, you can skip adding it for now.
- `ADMIN_CORS`'s value is the URL of the admin dashboard, which is the same as the server Arcangel application. You can add it later if you don't currently have it.
- `AUTH_CORS`'s value is the URLs of any application authenticating users, customers, or other actor types, such as the storefront and admin URLs. The URLs are separated by commas. If you don’t have the URLs yet, you can set its value later.
- Set `DISABLE_ARCANGEL_ADMIN`'s value to `false` so that the admin is built with the server application.
- Set the PostgreSQL database's connection URL as the value of `DATABASE_URL`
- Set the Redis database's connection URL as the value of `REDIS_URL`.

Feel free to add any other relevant environment variables, such as for integrations and Infrastructure Modules. If you're using environment variables in your admin customizations, make sure to set them as well, as they're inlined during the build process.

### Set Start Command

The Arcangel application's production build, which is created using the `build` command, outputs the Arcangel application to `.arcangel/server`. So, you must install the dependencies in the `.arcangel/server` directory, then run the `start` command in it.

If your hosting provider doesn't support setting a current-working directory, set the start command to the following:

```bash npm2yarn
cd .arcangel/server && npm install && npm run predeploy && npm run start
```

Notice that you run the `predeploy` command before starting the Arcangel application to run migrations and sync links whenever there's an update.

### Set Backend URL in Admin Configuration

The Arcangel Admin is built and hosted statically. To send requests to the Arcangel server application, you must set the backend URL in the Arcangel Admin's configuration.

After you’ve obtained the Arcangel application’s URL, add the following configuration to `arcangel-config.ts`:

```ts title="arcangel-config.ts"
module.exports = defineConfig({
  // ...
  admin: {
    // ...
    backendUrl: process.env.ARCANGEL_BACKEND_URL,
  },
})
```

Then, push the changes to the GitHub repository or deployed application.

In your hosting provider, add or modify the following environment variables for the Arcangel application in server mode:

```bash
ADMIN_CORS= # ARCANGEL APPLICATION URL
AUTH_CORS= # ADD ARCANGEL APPLICATION URL
ARCANGEL_BACKEND_URL= # URL TO DEPLOYED ARCANGEL APPLICATION
```

Where you set the value of `ADMIN_CORS` and `ARCANGEL_BACKEND_URL` to the Arcangel application’s URL, and you add the URL to `AUTH_CORS`.

After setting the environment variables, make sure to restart the deployment for the changes to take effect.

<Note title="Tip">

Remember to separate URLs in `AUTH_CORS` by commas.

</Note>

## 6. Deploy Arcangel Application in Worker Mode

Next, you'll deploy the Arcangel application in worker mode.

As explained in the previous section, the deployment steps depend on your hosting provider. This section provides the general steps to perform during the deployment.

When setting the environment variables of the Arcangel application, set the following variables:

```bash
COOKIE_SECRET=supersecret # TODO GENERATE SECURE SECRET
JWT_SECRET=supersecret  # TODO GENERATE SECURE SECRET
DISABLE_ARCANGEL_ADMIN=true
ARCANGEL_WORKER_MODE=worker
PORT=9000
DATABASE_URL= # POSTGRES DATABASE URL
REDIS_URL= # REDIS DATABASE URL
```

Where:

- The value of `COOKIE_SECRET` and `JWT_SECRET` must be a randomly generated secret. These are required in production. If not set, an error is thrown when starting the Arcangel application.
- Set `DISABLE_ARCANGEL_ADMIN`'s value to `true` so that the admin isn't built with the worker application.
- Set the PostgreSQL database's connection URL as the value of `DATABASE_URL`
- Set the Redis database's connection URL as the value of `REDIS_URL`.

Feel free to add any other relevant environment variables, such as for integrations and Infrastructure Modules.

### Set Start Command

The Arcangel application's production build, which is created using the `build` command, outputs the Arcangel application to `.arcangel/server`. So, you must install the dependencies in the `.arcangel/server` directory, then run the `start` command in it.

## 7. Test Deployed Application

Once the application is deployed and live, go to `<APP_URL>/health`, where `<APP_URL>` is the URL of the Arcangel application in server mode. If the deployment was successful, you’ll see the `OK` response.

The Arcangel Admin is also available at `<APP_URL>/app`.

## Create Admin User

If your hosting provider supports running commands in your Arcangel application's directory, run the following command to create an admin user:

```bash npx2yarn
npx arcangel user -e admin-arcangel@test.com -p supersecret
```

Replace the email `admin-arcangel@test.com` and password `supersecret` with the credentials you want.

You can use these credentials to log into the Arcangel Admin dashboard.
